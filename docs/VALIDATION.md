用户重启后，`IsSecureEventInputEnabled=false`，系统未报告锁屏。最终应用枚举到同一第一代蓝牙设备，执行 `probe 4`（默认设备槽位 1）成功退出，七个 ROOT 查询均得到匹配回复：

```text
0001 FEATURE_SET            index=01

1a00 PRESENTER_CONTROL      index=09
1a01 SENSOR_3D              index=0c
```

这验证了该蓝牙设备的 HID++ 长报文发送、接收、回复匹配及动态索引发现；`unavailable` 来自设备回复而非超时。尚未读取电量数值、配置按键、启用传感器或验证遥控器效果联动。先前功能查询受阻的状态已经解除。以下软件测试表为前一阶段记录。

### 前进键采集与只读配置查询

用户随后短按前进键一次、再按三次。hidapi 与独立 IOHIDManager 对照（同时注册原始报文和输入值回调）均未收到对应按键事件；期间查询回复均可被两路读取。系统安全输入保持关闭，不能把这一轮失败归因于锁屏。用户当时没有可观察的翻页页面，OS 是否响应按键仍未知。

新增只读 `inspect 4` 成功读取电量 `current=100 next=75 status=0x00` 与 7 个控制项。当前配置：`0050` 转发标志 `0000`；顶键长按 `00d8` 为 `0011`；切换高亮 `00df`、前进短按 `00d9`、前进长按 `00da`、后退短按 `00db`、后退长按 `00dc` 均为 `0001`。所有映射目标仍为自身。标志 bit 0 表示转交软件，bit 4 表示原始 XY 转发；这是查询到的原有状态，本程序未设置这些标志。它尚不能解释为什么按键通知未到达。

[25 条原始只读回复](qa/bluetooth-readonly-replies.hex) 来自该第一代设备、Bluetooth、`ff43:0202` 集合、macOS 27.0。顺序为 7 条功能查询，以及电量功能发现/读取、控制功能发现、控制数查询与每个控制项的两次查询。它们不是按键录制样本，不含序列号。未取得设备触发效果的验收证据。

### 第三方软件隔离

按用户要求，停止 Options+ 输入代理与 BetterMouse；未找到 OpenLogi 进程。Options+ 的当前登录会话任务 `gui/501/com.logi.cp-dev-mgr` 已通过 `launchctl bootout` 临时卸载，避免停止后自动重启。没有修改 LaunchAgent 文件或永久启动设置。此前的诊断采集进程也已停止，随后重新开始隔离采集。

隔离后 IORegistry 不再显示 Options+ / BetterMouse 打开的 Spotlight 客户端。Karabiner 客户端的 `ClientOpened=false`，未结束它；仍运行的 root 权限 Logi 更新服务没有打开该设备。再次只读查询发现 7 个控制项的 reporting 标志全部为 `0000`，映射目标仍为自身。此变化发生在退出其他软件之后，本程序没有发送配置修改请求。它证明了共存软件影响设备配置，是否解决按键缺失仍需隔离后的实机输入验证。

### 隔离后的首个真实按键样本

用户随后短按前进键一次，hidapi 收到下列两条原始报文，间隔 60 毫秒：

```text
47600ms 01 00 4f 00 00 00 00 00
47660ms 01 00 00 00 00 00 00 00
```

设备蓝牙 HID 描述符规定 report ID 1 为修饰键字节加 6 个键码，没有额外 reserved 字节。第一条包含 Keyboard RightArrow 使用码 `4f`，第二条全部键码清零，符合按下与松开。样本保存于 [bluetooth-next-shortpress.hex](qa/bluetooth-next-shortpress.hex)。这是成功的实机按键采集证据；尚未验证顶键状态或遥控器效果联动。因同时停止两个软件，不能据此单独归因于 Options+ 或 BetterMouse。

### 默认顶键移动与临时状态通知

用户执行“按住顶部小圆键移动约 3 秒，继续按住静止约 3 秒，再松开”。[完整样本](qa/bluetooth-top-default-movement.log) 共 520 条，全部是 report ID 2；16 位鼠标按钮掩码始终为零，没有独立顶键按下/松开通知。报文时间范围 18189–32320 毫秒，最后两条间隔约 7.2 秒。因此停止运动不能用来判断松开，也不能保证按住静止时效果保持。

新增 `watch-top` 诊断命令与可复用 Rust 顶键通知解码/配置生命周期代码。它验证能力与原状态，只修改 `00d8` 的临时 divert 位。首次实机写入的回复载荷为零，不符合公开 v2 文档的回显描述；程序报错并尝试恢复，独立查询确认 7 个控制项全部仍为 `0000`。已据实兼容空回复，开启与恢复都强制独立读回，不能仅凭空回复判断成功。该设备 ROOT 查询显示 0x1b04 版本为 3。[首次配置原始回复](qa/bluetooth-top-empty-config-ack.hex) 共 7 条，包含功能发现、控制信息、原状态以及开启/恢复的空回复。

最终 bundle 在同一蓝牙设备上通过四种恢复检查：正常 2 秒超时，以及收到 SIGTERM、SIGINT、SIGHUP。三种信号检查期间，独立 `inspect` 确认只有 `00d8` 的 reporting 变为 `0001`；退出后 7 项标志全部恢复 `0000`，映射目标均与测试前相同。每次退出码为 0，并有 `RESTORED and verified`。这些是配置与清理证据，不是用户按键样本；信号检查期间的 18 条采集均为 `inspect` 查询回复。[完整检查记录](qa/bluetooth-top-restoration.json)。

当前 20 项自动测试通过：原有 12 项，加 8 项顶键状态和配置生命周期检查。新增覆盖丢失写入确认、空固件回复、错误读回、Rust unwind、恢复错误传播、已有接管不覆盖、其他标志/映射保留，以及只接受对应设备的明确按键通知。Clippy 所有 target 无警告，格式检查通过，ARM64 release 已重新构建与签名。真实按住/静止/松开事件和原生鼠标运动是否保留，仍待下一轮用户操作。

### 顶键真实通知与蓝牙聚光验收

开启临时通知后，用户执行按住移动、继续按住静止、松开。[本轮动作样本](qa/bluetooth-top-diverted-hold.log) 共 860 条：858 条 report 2 鼠标移动，加两条 HID++ 通知：

```text
49183ms 11 ff 07 00 00 d8 00 00 00 00 00 00 00 00 00 00 00 00 00 00
73737ms 11 ff 07 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

按住到松开相隔 24.554 秒，运动报文最大间隔 10.904 秒。蓝牙通知地址为 `ff`，不同于查询回复的 `01`；原解码器因此未识别状态，未自动结束采集。随后通过 SIGTERM 正常停止，`RESTORED and verified` 加独立查询确认恢复原值。原日志后续另含 18 条只读查询回复，动作样本已排除它们。[状态日志](qa/bluetooth-top-diverted-hold.status) 因此记录总数 878。新解码器按连接方式选择通知地址，回归测试直接使用[真实两帧](qa/bluetooth-top-diverted-hold.hex)，不再以停止运动推断释放。

GUI 接入顶键后，首次启动和 SIGTERM 恢复通过[检查](qa/bluetooth-gui-cleanup.json)，但同进程断开后重连触发崩溃。系统报告 `EXC_BREAKPOINT / SIGTRAP`，故障线程 `spotlight-hid` 位于 `CFRunLoopAddSource → IOHIDDeviceScheduleWithRunLoop → IOHIDManagerSetDeviceMatchingMultiple`。hidapi 全局管理器绑定在已经退出的初始读取线程运行循环上。已将初始化与枚举移到 AppKit 主线程，设备读写保留在后台。崩溃遗留的临时标志根据已记录的默认原值显式恢复，[恢复前后记录](qa/bluetooth-gui-crash-recovery.json) 验证其他设置未改；应用不会自动强制重置。

修复后通过 CUA 点击“断开遥控器”和“连接遥控器”，PID 12167 保持不变；界面分别显示断开及蓝牙连接状态，独立查询显示顶键 `0000 → 0001`，其余六项仍为 `0000`。[复测记录](qa/bluetooth-gui-reconnect.json)。控制面板截图已检查，无控件重叠或连接文案截断。点击“立即隐藏”有对应 UI 更新；CUA 模拟 `⌃⌥⌘H` 未观察到状态变化，因此该快捷键仍未通过实际验收。

用户曾在放大模式下操作顶键，应用处理到按住/松开，但采集未提供帧，覆盖窗口可见数均为 0；这不是放大成功证据。切换至聚光并结束预览后，用户完成相同动作，并确认“**三项都正常**”：聚光跟随移动、按住静止保持、松开消失。应用日志对应 `REMOTE TOP pressed overlay_windows_visible=1` 与 `released overlay_windows_visible=0`。[验收记录](qa/bluetooth-spotlight-acceptance.json)。这是蓝牙聚光的真实端到端验收，不代表 USB、多屏、全屏、会议共享或实时放大也已通过。

最终 23 项自动测试、Clippy 所有 target 和格式检查通过；ARM64 应用已重建。最终包的三种原生离屏绘制检查再次通过（聚光中心 alpha 0、激光/放大中心 alpha 1），证明此次状态/UI 修改未破坏这些绘制入口。未以离屏结果替代真实放大验证。
