# 课堂倒计时：设计、实施计划与验收计划

状态：2026-11-15 起草并完成代码实现。步骤 0–4 中可离线完成的部分与步骤 6 的文档更新已完成，7.2 的全部自动测试通过。阶段 0 实机验证（7.1）、无设备界面验收（7.3）和实机验收（7.4）尚未执行，因此本文仍是验收依据，不是完成记录。实现与证据分类见 `docs/VALIDATION.md` 的 2026-11-15 一节。

## 1. 目标

讲课时临时宣布"课堂练习，限时 5 分钟"。讲者不回到电脑，只用翻页器完成三件事：

1. 调出倒计时窗口。
2. 设定分钟数。
3. 开始倒计时，观众能在屏幕上看到剩余时间。

到时间后遥控器振动，屏幕提示"时间到"。

### 不在范围内

- 现有的"演讲计时"（最多 3 个定时点、菜单栏正计时）保持不变，两者互相独立。
- 指针速度调节（HID++ `2205`）另行计划。
- 秒级设定、多个倒计时并行、提示音。
- USB 接收器和 Spotlight 2 的验收。本功能先在第一代蓝牙设备上验收。

## 2. 假设与待确认项

| 编号 | 假设 | 不成立时的处理 |

| A2 | 设定期间短按"下一页"加 1 分钟，短按"上一页"减 1 分钟 | 改用第 9 节的备选方案 |
| A3 | 短按键 `00d9`、`00db` 可以被临时接管，接管期间设备不再发送方向键 | 改用第 9 节的备选方案 |

## 3. 交互设计

### 3.1 状态

```text
空闲 ──长按──▶ 设定 ──3 秒无操作──▶ 运行 ──到 0──▶ 结束提示 ──5 秒──▶ 空闲
                │                      │
                └──────长按────────────┴──▶ 空闲（取消）
```

| 状态 | 屏幕 | 短按翻页键 | 长按"倒计时"键 |
|---|---|---|---|
| 空闲 | 无窗口 | 正常翻页 | 进入设定 |
| 设定 | 屏幕中央大窗口：时间和操作提示 | 加减 1 分钟，不翻页 | 取消，回到空闲 |
| 运行 | 屏幕右上角小窗口：`mm:ss` | 正常翻页 | 停止，回到空闲 |
| 结束提示 | 屏幕中央"时间到"，持续 5 秒 | 正常翻页 | 立即关闭提示 |

### 3.2 规则

- 进入设定时的初始值是上次使用的分钟数，首次为 5。
- 可设范围 1–99 分钟。到达边界后继续按键无效。
- 每次加减都把"3 秒自动开始"重新计时。
- 设定期间不设"确认键"。原因：单击顶键会由设备发出鼠标左键点击，放映软件会把它当作翻页。接管顶键点击会扩大改动范围，收益小。
- 设定期间，另一个长按键配置的动作不执行，避免误触黑屏或结束放映。
- 剩余 10 秒内数字变为红色。
- 倒计时到 0 时振动一次。振动失败不影响屏幕提示。
- `⌃⌥⌘H`（立即隐藏）同时取消设定或停止倒计时，并撤销按键接管；`Esc` 仅清除黑屏、方框等停留画面特效，不取消倒计时。
- 聚光、激光等效果在设定和运行期间照常可用。

### 3.3 无遥控器入口

菜单栏增加一项"课堂倒计时…"。行为与长按相同：进入设定，3 秒后按当前值开始；运行中再次选择则停止。这个入口用于无设备测试，也用于遥控器未连接时的手动操作。无遥控器时不能加减，使用上次的分钟数。

### 3.4 窗口

- 每个显示器一个窗口，与现有屏幕提示（`show_toast`）同类型：无边框、不激活、点击穿透、层级高于黑屏。
- 设定窗口：居中，时间约 96 pt，下方一行提示"下一页 +1 分钟 · 上一页 −1 分钟 · 3 秒后开始"。
- 运行窗口：右上角，时间约 48 pt。
- 显示器增减或缩放变化时，随现有的 `refresh_screens` 重建。

### 4.2 状态机（`src/countdown.rs`）

```rust
pub enum Countdown {
    Idle,
    Setup { minutes: u32, start_at: f64 },
    Running { deadline: f64 },
    Finished { until: f64 },
}
```

接口，全部以调用方传入的 `now`（秒）为时间来源：

| 方法 | 作用 |
|---|---|
| `toggle(now, last_minutes)` | 长按或菜单：空闲→设定；设定、运行、结束提示→空闲 |
| `adjust(delta, now)` | 设定状态下加减分钟并重置 `start_at`；其他状态无效 |
| `tick(now) -> Option<Change>` | 设定到点→运行（`Started(minutes)`）；运行到点→结束提示（`TimeUp`）；提示到点→空闲（`Closed`） |
| `cancel()` | 立即回到空闲 |
| `remaining(now)` | 运行状态下的剩余秒数，向上取整 |
| `wants_page_keys()` | 仅设定状态为真；接线层据此决定接管或撤销 |

接线层只在 `wants_page_keys()` 的值发生变化时向设备线程发命令。这样"何时接管"只有一个判断来源。

### 4.3 短按键接管（`src/macos/remote.rs`）

新增命令和事件：

```rust
enum Command { Vibrate(String), PageKeys(bool) }
enum Gesture { DoubleClick, NextHold, BackHold, NextShort, BackShort }
enum Event { ..., PageKeys(Vec<(u16, Reporting)>) }  // 当前由本会话接管的短按键及其原值
```

- 收到 `PageKeys(true)`：对 `00d9`、`00db` 分别调用现有的 `TemporaryTopButton::start_or_adopt`。它已包含能力检查、原值读取、写入和读回校验，也会拒绝已被其他软件接管的按键。
- 收到 `PageKeys(false)`、线程退出或设备出错：对已接管的短按键调用 `finish()`，恢复并校验原值。恢复失败的按键并入现有的 `unrestored` 列表。
- 每次接管状态变化后发送 `Event::PageKeys(...)`。主线程用它更新 `unrestored` 文件，与现有 `Event::Connected` 的处理方式一致。应用被强制结束后，下次启动能识别并接回自己留下的接管。
- `Buttons::handle` 在按下沿把 `00d9`、`00db` 转为 `NextShort`、`BackShort`。
- 接管过程中的 HID++ 事务使用 `transact_observing`，避免丢失同时到达的顶键通知。

**只接管成功一个键时**，立即撤销已接管的那个，按接管失败处理。不允许出现一个键翻页、另一个键调时间的状态。

**接管失败时**（设备不支持，或按键被其他软件占用）：设定窗口照常出现，提示行改为"无法用翻页键调整，3 秒后按 N 分钟开始"。倒计时功能仍可用，只是不能调整。

### 4.4 主线程接线（`src/macos/countdown.rs`、`src/macos/mod.rs`）

- `perform_hold` 增加 `HoldAction::Countdown` 分支，调用 `toggle`。
- 设定状态下，`NextHold`、`BackHold` 中未配置为倒计时的那个不执行动作。
- `NextShort`、`BackShort` 调用 `adjust(±1, now)`。
- `tick` 中调用状态机的 `tick`：
  - `Started(minutes)`：保存 `countdown_minutes`，撤销接管。
  - `TimeUp`：发送振动命令，切换到"时间到"窗口。
  - `Closed`：隐藏窗口。
- 设定或运行期间由常驻定时器驱动刷新，仅在文字或状态变化时更新控件；空闲时不增加任何周期性工作。
- 遥控器在设定期间断连：设备线程退出时按现有流程恢复或记录按键；状态机不受影响，3 秒后按当前值开始。

### 4.5 诊断与恢复命令（`src/main.rs`、`src/diagnostics.rs`）

- `watch-page-keys DEVICE [SECONDS] [INDEX]`：临时接管 `00d9`、`00db`，输出解码后的按下和松开事件，同时输出期间收到的键盘报文（report ID `01`），结束时恢复并校验。结构与现有的 `watch-controls` 相同。
- `recover-controls-default`：把 `00d9`、`00db` 加入可恢复的按键列表，接受条件不变（原值为 `0000` 且映射到自身）。

### 4.6 数据与权限

- 设置文件新增一行 `countdown_minutes=N`。旧文件没有这一行时取 5。
- 不需要新的系统权限。本功能不发送按键，不采集屏幕。

## 5. 风险

| 风险 | 后果 | 对策 |
|---|---|---|
| 应用在设定期间被强制结束 | 短按键保持被接管，放映中不能翻页 | 接管窗口只有几秒；`unrestored` 文件记录原值，重启应用后接回并恢复；`recover-controls-default` 作为手动恢复手段 |
| 接管或撤销耗时过长 | 长按后立即短按，第一下仍会翻页；或倒计时开始后第一下不翻页 | 阶段 0 实测耗时。超过 300 ms 时，把按键能力查询提前到连接时执行 |
| 设定期间长按翻页键的固件行为未知 | 可能同时收到短按和长按通知，造成误加减 | 阶段 0 记录实际报文，按结果决定是否忽略长按前的那次短按 |
| Mos、Karabiner 或 Logi Options+ 占用同一按键 | 接管被拒绝 | 按 4.3 的失败路径降级，并在控制面板显示原因 |
| 安全输入开启（密码框获得焦点） | 设备读取暂停，设定期间按键无响应 | 沿用现有暂停逻辑；3 秒后仍按当前值开始，撤销接管延后到恢复读取时 |

- 不为倒计时增加控制面板分组。唯一的配置入口是长按动作下拉项。
- 不改动现有演讲计时的行为和界面。

## 9. 备选方案：预设值循环

仅在假设 A2 或 A3 不成立时采用。

- 长按一次进入设定并显示第一个预设值；设定期间每次长按切换到下一个预设值（1、3、5、10、15 分钟）；3 秒无操作后开始。
- 运行中长按停止倒计时。
- 不接管短按键，因此没有第 5 节的前三项风险。
- 缺点：不能设定任意分钟数；取消设定需要等待并在开始后再长按一次，或使用 `⌃⌥⌘H`。

采用备选方案时，第 4.3 节和步骤 3 取消，状态机的 `adjust` 改为 `next_preset`，测试 T3、T4、T13–T16 和验收 D2、D9 相应调整。
